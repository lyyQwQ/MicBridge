# 双端状态优先界面重设计

## 目标与依据

采用用户已选方向 A「状态优先单屏」：Android 与 Windows 首屏清楚表达连接、采集和下一步操作，降低日常配置噪声，改善视觉层级。用户已授权建任务并加入 Windows 配对任务栏闪烁。用户已批准本计划并允许修改错误状态逻辑（「批准，并允许改错误状态逻辑」），任务进入 in_progress 实施。

审计原文归档于 `research/ui-audit.md`（来源 `local://ui-audit.md`）；问题编号沿用原文 1–16，原文行号是审计时快照，实施前需重新定位。原始截图与脚本位于 `build/diag/ui-audit-*.png`、`build/diag/ui_render_test.dart`。Android 原审计没有实机截图；替代字体渲染不能证明实机字形与图标正确，对比度和忘记按钮图标缺失原因尚未验证。

## 范围与硬约束

- 不新增依赖。Flutter 为双端唯一界面，.NET 保持无窗口。
- 不改平台接口：保留 `_run`、配对弹窗生命周期（去重、失效、关闭即拒绝）、轮询、设备刷新和 `platform_bridge` 协议。经用户批准，本地错误 `_connectionError` 的清除时机改为按时序（见 R6），不改平台协议。Android 点击发现项直接连接仅重接 UI 回调至已有连接路径；Windows 闪烁使用独立窗口提醒通道，不扩展音频/配对协议。
- 保留两端忘记设备、Windows 手动 TCP 连接、电脑主动连接已记住手机、默认「跟随系统」的麦克风选择、手动开始/停止采集。
- 暂停保持时间为 3 秒；本任务不修改计时策略。采集行为文案统一为「采集」；Windows 外部应用的录音检测与 CABLE Output 专有名称可保留准确含义。
- 禁止置顶、抢前台和主动恢复最小化窗口。手机仅在本应用实际位于前台且无其他应用/通知栏遮挡时截图；Windows 使用后台窗口截图。
- 改状态文案和发现点击行为时，同步 `.trellis/spec/frontend/state-management.md`。
- 实施前置依赖：Android 发现列表闪烁修复先合入，再基于其结果改 UI；不得在本任务重写发现流或合并其状态逻辑。
- 不覆盖用户或其他代理未提交改动，不清理审计临时文件。

## 非目标

不重写配对、信任、网络发现、音频链路或自动采集策略；不加托盘、Toast、通知权限、多页面导航、云服务或第三方 UI 库；不在规划阶段修改产品代码或运行实机操作。

补充验收约束：R1/R2 的 Windows 首屏状态区必须实时展示 listenerActive 的两种检测结果，不可用静态自动采集说明代替。R5 的 Android ⋮ 菜单在所有状态始终含「权限检查」，沿用 requestPermissions 调用，busy 时禁用但不隐藏。R4 的 Android 条目复用 `_selectComputer(endpoint)` + `_connect()`，保留 expectedDeviceId，busy 时禁用；手动改地址后不得携带旧 ID。配对边界为保持生命周期语义和原有顺序。

R6 以现有字符串为输入：稳定标识及兜底文案见 design.md「错误展示」。错误按时序只显示一处：本地命令/刷新失败写入 `_connectionError`；之后到达的、与上一快照不同（state、connected 或 detail 变化）且为已连接或 error 的快照比它更新，清除本地错误；重复的相同快照（Windows 两秒轮询）和未连接快照不清除；新命令开始时 `_run` 照旧清除。展示时本地错误存在则显示本地错误，否则 snapshot.state == error 时显示快照 detail。由此：失败后收到成功快照隐藏旧错误且之后断连不重现；失败后收到新 error 快照只显示新错误；成功后本地再失败会显示，不被相同的成功快照遮蔽。未知错误提示「操作未完成，请重试；若仍失败，请检查连接与设备，并查看诊断日志。」

R3 的审批方案为每请求闪烁 3 次，窗口已在前台时跳过，用户切回时停止；R8 的 900 断点为 LayoutBuilder 可用逻辑宽度。
